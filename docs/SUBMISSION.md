# Подготовка к сдаче

Промежуточный показ назначен на 25 ноября 2026 года, окончательная сдача — на первую неделю декабря. На показе диспетчер работает с компьютера, а техник получает заявку и фиксирует результат на телефоне.

## До публикации

- Проверь ФИО, группу, курс, направление и профиль на титуле. Руководителя, подписи и оценку нельзя подставлять без фактических данных.
- Пройди сценарий `TWO_DEVICES.md`; отметь реальные устройства и результаты.
- Убедись, что понимаешь обработку запроса, внешние ключи, роль `version`, права и цикл статусов. Материал — `report/DEFENSE.md`.
- Запусти `python -m pytest -q` в окружении проекта.
- Проверь список файлов для Git: не публикуй `data/`, `.venv/`, `.env`, ключ сессии, личные данные или локальные журналы.

## GitHub

Публикуется содержимое папки **kontur**, а не всё окружение разработки. Создай репозиторий в своём аккаунте. Название, например, `kontur-coursework`. Добавь исходники, README, requirements, tests, docs, report и workflow. Папка `.github` начинается с точки и тоже нужна.

При работе через Git из этой папки:

```bash
git init
git add .
git status --short
```

Перед коммитом внимательно проверь этот список. После этого сделай коммит и отправь в собственный созданный репозиторий обычным push; адрес репозитория должен быть твоим фактическим адресом, а не вымышленной ссылкой из инструкции. Не делай force push.

Открой страницу репозитория и проверь, что README отображается, исходники доступны, ссылка на пояснительную записку открывается, а Actions завершился успешно (если включён). Выполни установку из чистой копии по README.

По порядку, указанному в сообщении группы, ссылку нужно передать Никите Ремизову. Эта инструкция не означает, что публикация или отправка уже выполнена. Репозиторий преподавателя со стилем LaTeX не является твоим готовым проектом.
