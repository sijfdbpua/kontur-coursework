# Протокол проверки «Контур»

19 ноября 2026 г. на Ubuntu из корня проекта выполнена команда `python -m pytest -q`. После проверки авторства записей в журнале получен результат `36 passed in 3.73s`. Python 3.14.4, Flask 3.1.3, SQLite 3.46.1, pytest 9.2.0.

| Объект | Что наблюдалось | Где воспроизвести |
|---|---|---|
| Жизненный цикл | После назначения, начала, комментария, завершения и приёмки статус `closed`, версия 5. Сохранились комментарий и автор результата | `test_two_devices_full_workflow` |
| Доступ | Чужой номер заявки технику возвращает 404, запросы диспетчерских действий отклоняются | `test_technician_only_own_tickets`, `test_technician_cannot_create_export_assign_or_prioritize` |
| Конфликт | Два сеанса изменяют одну версию. Второй получает 409. Сохраняются результат первого и два события (создание и смена приоритета) | `test_optimistic_conflict_preserves_newer_data` |
| История результата | Диспетчер меняет приоритет выполненной заявки, закрывает её и возвращает в работу. Назначение сохраняется. В журнале остаётся ровно одна исходная запись о результате с авторством техника | `test_reopen_retains_assignment_and_preserves_history` |
| Валидация, сессии и выгрузка | Проверены ограничения длины/формата, отказ при неверном токене, смена токена при входе, завершение сеанса, экранирование формулы в CSV | `tests/test_api.py` |
| Хранение и копия | Новое приложение открыло ту же заявку из сохранённой базы. Копия SQLite содержит зафиксированную запись из WAL и проходит проверку целостности. Существующая копия защищена от перезаписи | `test_persistence_on_restart_and_seed_refuses_overwrite`, `tests/test_backup.py` |

11 ноября во встроенном браузере проверены два отдельных сеанса на одном компьютере. Диспетчер создал и назначил КН-0013. Техник при размере окна 390 × 844 открыл её, начал работу, добавил комментарий и передал результат проверки HDMI. У диспетчера в открытой карточке появились события исполнителя и предложение обновить данные. Авторизованные сеансы работали с одним сервером через `127.0.0.1` и `localhost`, с разными cookie для этих имён.

19 ноября в двух независимых сеансах Chrome пройден весь цикл от регистрации с компьютера до закрытия после работы техника. Итоговая версия заявки — 5, в истории сохранилось восемь событий. Мобильная карточка поместилась в окно шириной 390 CSS-пикселей. [Протокол и снимки экранов](UI_CHECK.md).

Комплект для передачи распакован в пустой каталог. В новом виртуальном окружении установлены зависимости из `requirements-dev.txt` и повторно пройден весь набор тестов. Команда `init-demo` создала трёх пользователей, шесть единиц оборудования и двенадцать заявок. После запуска Waitress проверены главная страница и вход двух независимых HTTP-клиентов. В очереди диспетчера оказалось двенадцать заявок, в очереди техника Михаила — пять назначенных ему заявок.

Проверки физического телефона, конкретной Wi-Fi-сети в аудитории и нагрузки реальных пользователей остаются отдельными испытаниями. Для физической проверки подготовлен [полевой протокол](TWO_DEVICES.md).
